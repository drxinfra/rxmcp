# Подключение к Claude Desktop, Claude Code и Cursor

Инструкция для обычного пользователя RX. Ничего настраивать в системе не нужно, права администратора не требуются.

## 1. Поставить rxmcp

macOS и Linux:

```sh
curl -fsSL https://drxinfra.ru/dl/rxmcp/install.sh | sh
```

Windows: скачайте `rxmcp-<версия>-windows-amd64.zip` со страницы [Releases](https://github.com/drxinfra/rxmcp/releases), распакуйте, например в `C:\Program Files\rxmcp`.

Если браузер пометил скачанный файл карантином, macOS откажется его запускать. Лечится одной командой: `xattr -d com.apple.quarantine rxmcp`. Установщик это делает сам.

## 2. Ответить на три вопроса

```sh
rxmcp setup
```

- **Адрес RX** — то, что вы набираете в браузере, например `https://rx.company.ru`. Хвост `/integration` подставится сам.
- **Логин в RX** — ваш обычный логин. По нему сервер понимает, чьи задания показывать.
- **Способ входа** — `password`, если в RX вход по паролю; `cookie`, если вход через SSO, Keycloak или домен (в этом случае см. шаг 3).

Дальше `setup` проверит связь с RX (только чтение) и сам пропишет сервер в найденные на машине клиенты. Перезапустите Claude Desktop или Cursor; Claude Code подхватывает настройку сам.

## 3. Если вход через SSO

### Keycloak или другой OIDC-провайдер: один раз `rxmcp login --sso`

```sh
rxmcp login --sso
```

Команда напишет адрес провайдера. Откройте в браузере его личный кабинет (адрес команда подскажет, вы там уже вошли), `F12` → **Network** → обновите страницу → первый запрос → **Request Headers** → `cookie` → **Copy value** и нажмите Enter. Дальше rxmcp сам берёт новую cookie RX, когда старая истекает. Повторить команду нужно, только когда истечёт сессия провайдера, ассистент скажет об этом.

### Любой другой вход: cookie из браузера

1. Откройте RX в браузере и войдите как обычно.
2. `F12` → вкладка **Application** (в Firefox — **Хранилище**) → **Cookies** → выберите адрес RX.
3. Скопируйте значение cookie **`sungero_client`**.
4. Выполните `rxmcp login --paste` — значение возьмётся из буфера обмена. Или `rxmcp login`, вставьте значение в терминал и нажмите Enter. В WSL буфер обмена Windows тоже подходит.

Сессия RX живёт недолго. Когда ассистент скажет, что сессия истекла, повторите шаг 4. **Перезапускать Claude не нужно**: cookie лежит отдельным файлом, сервер перечитывает его на каждом запросе.

## 4. Проверить

```sh
rxmcp check
```

Команда делает десяток запросов только на чтение и печатает, что работает. Все строки с галочками — можно пользоваться.

В Claude спросите, например: «какие у меня задания просрочены?», «покажи карточку документа 44592», «что на доске команды разработки», «найди в базе знаний статью про отпуск».

## 5. Разрешить запись (необязательно)

По умолчанию сервер только читает. Чтобы ассистент мог заводить карточки на доске, отправлять задачи и выполнять задания:

```sh
rxmcp config set RXMCP_ALLOW_WRITE=1
```

Каждое такое действие ассистент сначала показывает целиком и спрашивает подтверждение.

## Если что-то не так

| Что видно | В чём дело |
|---|---|
| `RX отклонил учётку (401)` при `cookie` | сессия истекла: `rxmcp login --paste`, при входе через провайдера один раз `rxmcp login --sso` |
| `сессия провайдера входа истекла` | войдите в RX в браузере и повторите `rxmcp login --sso` |
| `RX отклонил учётку (401)` при `password` | у логина в RX тип входа не «пароль» — используйте `cookie` |
| `не задан адрес RX` | профиль пуст: `rxmcp setup` |
| сервер не появился в клиенте | клиент не перезапущен, либо путь к бинарнику изменился: `rxmcp install --apply` |
| `сертификат не проверен` | у RX сертификат своего УЦ: `rxmcp config set RXMCP_CA=/путь/ca.pem` |
| инструментов записи не видно | они скрыты, пока не включён `RXMCP_ALLOW_WRITE=1` |
| любая запись отвечает «Пользователь отменил действие», формы не было | клиент не показывает форму подтверждения: `rxmcp config set RXMCP_CONFIRM=0` и перезапустить сервер в клиенте |

Что настроено сейчас — `rxmcp config`. Где лежит профиль — `rxmcp config path`. Полный список настроек — `rxmcp help`.
